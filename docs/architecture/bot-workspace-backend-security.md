# Backend workspace trust boundary

Workspace receipt provenance is not established by hidden filenames, root mode bits or checksums in ordinary Home. Docker uses `astonish-bot-workspace-<scope>`: an ownership-labelled local volume that normal runtime session creation never mounts. Kubernetes uses `workspace-private/` beside `data/` in the exact scoped PVC reservation; normal execution mounts only `data/`. The existing `.owner` marker and UID/reservation/admission checks remain required. Ordinary Home `.head`, `.receipts` and `.revisions` are not adopted or migrated into trusted storage.

Both implementations use the same server-owned descriptor-relative Python program. The private `.workspace-lock` serializes publication, reads, snapshots, mutable writes and the entire script read/execute/publish transaction. File and directory quotas include prospective staging, not merely post-write detection. Limits remain 1 MiB per asset, 16 MiB revision bundle, 128 MiB task state and 512 MiB private workspace; accounting may conservatively reject a transaction when there is not enough room for both old and staged new bytes.

The helper stages and fsyncs bytes, announces readiness on its trusted control stream, and awaits approval. `sandbox.WithBotHomeWorkspaceCommitGuard(ctx, guard)` attaches the caller's live lease/permission/fence check, invoked after staging under the storage lock. Context cancellation and guard rejection send no commit approval. Launcher callers must install that guard; without it, backend context cancellation is checked but the backend cannot independently know application lease revocation. No generic Backend method signature changed.

Docker script execution receives verified pinned executable bytes and a copied state inventory via stdin, with **no durable volume mounted**. Network is disabled, root filesystem read-only, and scratch has a hard 128 MiB tmpfs aggregate capacity. All completed results inventory and validate scratch; nonzero exits, timeout, special objects, quota violations, excessive output and cancellation do not publish. Successful state is staged in private storage, guarded, and selected by Linux `renameat2(RENAME_EXCHANGE)`; old scratch state is removed while holding the shared lock. The trusted scratch supervisor drops the workload to UID/GID 65534, protects executable input with a root-owned non-writable directory/file, uses bounded disk capture rather than unbounded stdout pipes, and kills residual workload processes in its private PID namespace before inventory. Only the supervisor retains CHOWN/SETUID/SETGID/KILL capabilities; workload capabilities are cleared on the uid change. Kubernetes intentionally does not advertise script execution.

Evidence: `TestBotHomeWorkspaceRejectForgedOrdinaryHomeReceipt` was observed failing before the private-root change. Local Python and fake Kubernetes tests prove the filesystem/protocol only, not a real PVC or kubelet. `ASTONISH_TEST_TASK_WORKSPACE=1 ASTONISH_SANDBOX_IMAGE=<already provisioned local image> go test ./pkg/sandbox/docker -run '^TestBotHomeWorkspace($|ScratchPinnedInput)' -count=1 -v` exercises new owned physical volumes, SQLite continuity, ordinary Home receipt forgery, post-staging revoked writes/scripts, read/write/snapshot exclusion while a script holds the lock, failed/aggregate-overflow/link/timeout/cancelled scripts and unchanged durable state. Cleanup is exact-resource-only, without pruning or daemon restart.

On 2026-11-13, the physical command above passed against pre-existing local image `sha256:65d64672b5dc8747fb7e5c50b6806ae64fdc90431b23f7c457c05f7d301e96ae` (workspace test 29.17s; pinned-input test 0.44s). This evidence is backend-local, not production-factory acceptance or live Kubernetes certification.
