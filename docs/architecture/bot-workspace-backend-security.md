# Backend workspace trust boundary

Workspace receipt provenance is not established by hidden filenames, root mode bits or checksums in ordinary Home. Docker uses the separately ownership-labelled `astonish-bot-workspace-<scope>` volume; Bot session compute mounts it alongside ordinary Home for fixed internal persistence operations. Kubernetes uses `workspace-private/` beside `data/` in the exact scoped PVC reservation. Compiled dispatch validates the scoped `.owner` marker and existing UID/reservation/admission checks before opening roots. Ordinary Home `.head`, `.receipts` and `.revisions` are not adopted or migrated into trusted storage. These mounts and the shipped outer executable preserve the existing sandbox trust model; they do not establish isolation from privileged session processes.

`RunBotHomeWorkspace` implements `publish`, `resolve`, `read`, `write`, `snapshot` and `list` in compiled Linux code, sharing `homeOpen`/`homeDir`/`homeStat` confinement with FILES. Non-Linux invocation fails closed. Docker invokes `astonish-host node --internal-home-workspace` against the resolved physical container; Kubernetes invokes `--internal-scoped-home-workspace` using the existing file target and checks pod UID. Warm workspace operations do not create a helper or consult overlay Python. Legacy archive restore, knowledge operations and scratch still consume the server-owned Python constants and must not lose them before migration.

The private `.workspace-lock` serializes publication, reads, snapshots, mutable writes and legacy script transactions. Compiled reads never create a missing root or lock. File and directory quotas include prospective staging, not merely post-write detection. Limits remain 1 MiB per asset, 16 MiB revision bundle, 128 MiB task state and 512 MiB private workspace; accounting may conservatively reject a transaction when there is not enough room for both old and staged new bytes.

Compiled publication revalidates revision bytes, parent identity and head CAS after host approval. Mutable writes revalidate staged bytes and destination identity before rename. This closes substitutions while waiting on the fence, not arbitrary hostile-root races. Both transports close and join the request writer, propagating write errors. Linux fixture evidence: `TestCompiledWorkspaceRejectsFenceSubstitution`, `TestCompiledWorkspaceRoundTrip`, `TestCompiledWorkspaceReadDoesNotCreateAndSpecialFiles`, and bidirectional `TestCompiledWorkspacePythonReceiptCompatibility`. `TestCompiledWorkspaceNodeDocker` ran a freshly built binary in disposable Debian with no Python, exercising publish/resolve/read/write/snapshot. Warm Kubernetes routing is fake-client evidence only. Offline lifecycle, archive migration, nested commit-read lock behavior and physical Kubernetes cancellation/reaping remain separate acceptance work.

The helper stages and fsyncs bytes, announces readiness on its trusted control stream, and awaits approval. `sandbox.WithBotHomeWorkspaceCommitGuard(ctx, guard)` attaches the caller's live lease/permission/fence check, invoked after staging under the storage lock. Context cancellation and guard rejection send no commit approval. Launcher callers must install that guard; without it, backend context cancellation is checked but the backend cannot independently know application lease revocation. No generic Backend method signature changed.

Docker script execution receives verified pinned executable bytes and a copied state inventory via stdin, with **no durable volume mounted**. Network is disabled, root filesystem read-only, and scratch has a hard 128 MiB tmpfs aggregate capacity. All completed results inventory and validate scratch; nonzero exits, timeout, special objects, quota violations, excessive output and cancellation do not publish. Successful state is staged in private storage, guarded, and selected by Linux `renameat2(RENAME_EXCHANGE)`; old scratch state is removed while holding the shared lock. The trusted scratch supervisor drops the workload to UID/GID 65534, protects executable input with a root-owned non-writable directory/file, uses bounded disk capture rather than unbounded stdout pipes, and kills residual workload processes in its private PID namespace before inventory. Only the supervisor retains CHOWN/SETUID/SETGID/KILL capabilities; workload capabilities are cleared on the uid change. Kubernetes intentionally does not advertise script execution.

## Retained file transport (file-first implementation in progress)

The optional `BotHomeFilesBackend` keeps ordinary Home file operations separate from the Task workspace protocol. Docker mounts the independently retained Home in an owned helper and mounts the private workspace only for immutable content operations. Kubernetes uses its existing scoped attachment reservations and validates the helper UID and admitted pod specification. Neither listing nor opening a file allocates a missing Home or recreates the original run. The shared Docker/Kubernetes file-helper protocol maps an absent descriptor-relative file or directory to `store.ErrBotNotFound`, allowing authorized bootstrap code to create missing documents without misclassifying absence as a transport failure. Missing retained storage roots still fail closed; reads never provision those roots. Helper stderr is preserved with transport failures (including early EOF), so genuine setup, permission and process errors remain diagnosable rather than becoming a generic missing-file result.

Listings are metadata-only, paginated at 100 entries by default with a maximum of 500. Raw streams are not subject to the older buffered artifact reader's 16 MiB transport limit. File walks reject traversal, symbolic links, multiply linked regular files, special files and nested mount crossings. Mutation helpers stage and fsync bytes, validate expected prior bytes, await the trusted commit barrier, and atomically replace the selected file. Immutable snapshots use separate private object keys, so editing a working file does not rewrite a previously saved snapshot. These operations do not provide a whole-Home snapshot against arbitrary concurrent shell writers.

Closing a stream cancels its transport before joining an already pending EOF waiter; otherwise a paused remote exec could deadlock Close. `TestBotHomeFilesCloseInterruptsPendingJoin` exercises this ordering using a controlled transport. Kubernetes API/transport tests are not physical Kubernetes evidence.

`TestProductionBotWorkspaceDockerLive` additionally writes and streams a 22 MiB byte fixture, lists files after destroying the original test session, checks an immutable range after editing its working source, and verifies those retained working files in a replacement session. This proves the physical Docker backend path, not completed worker memory, end-to-end SQL content cutover or UI delivery integration. Typed disk persistence and retained reference selection are implemented separately; this transport fixture does not certify them. Fixture bytes test transport integrity, not media generation.

## Scoped service and pre-Home staging

`Services.BotFilesFactory` is preserved in request-scoped tenant clones. The production reader uses only the explicitly selected personal or team repository and never installs write authority. Team viewers authorized by the repository read the owner's retained binding, not a new viewer-owned Home. Private execution content is not made available to viewers. The daemon also constructs the read adapter in API-only mode without starting a worker.

Worker preparation installs a separate exact-run commit authorizer. `BotFileCommitStore.WithBotFileCommit` holds the existing transcript/root fence and checks the registered Home, accountable owner and active lease. The callback commits only already staged bytes; it must not re-enter the outer scoped repository (single-connection SQLite would deadlock). File capability wiring does not add tool grants or bypass mandate authorization.

The internal `botDiskContent` component stores pre-Home objects and team templates under a mandatory, preprovisioned `bot-content/` directory in the configured control-plane DataDir. Scope namespaces are hashes of structured ownership, not user-selected paths. Template ownership excludes a source Bot. Writes stage and fsync immutable objects, enforce a commit callback, and publish body-free references; opening validates kind/revision/name, ownership, byte count and SHA256. Symlinks, hardlinks and special files are rejected. The component can copy a staged object to registered retained Home, verify the destination and leave the original intact until a separate SQL reference update and authorized cleanup. Missing roots fail rather than selecting a host temporary directory or SQL body fallback.

The scoped disk codecs and production retained selection now use this component. `SelectBotHomeConfiguration` validates and atomically selects the complete supported Bot-owned typed reference closure, including Task candidates, run/outbox/knowledge content and Bot-linked events; independent intake/templates are not adopted. New selected writes use retained private content storage, not the ordinary working-file tree. Selection preserves staging for rollback and never deletes it. See [retained content selection](bot-retained-content-selection.md).

Generic Bot memory SQL/FTS/source-record removal and file-backed MEMORY.md remain pending. Public Bot backup/restore rejects legacy inline and reference-only SQL archives until the file-first archive protocol lands; complete reference-aware cleanup is separate work. DDL marker 4 remains DDL-only and does not convert old content. Do not treat these services as completed file-first Bot acceptance or physical Kubernetes/dedicated PostgreSQL proof.
