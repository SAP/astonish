# A2A streaming diagnosis

## Findings

The reported behavior consists of four distinct issues.

### 1. A2A intentionally drops token-level text events

`pkg/channels/manager.go:952-955` skips every ADK event where `event.LLMResponse.Partial` is true. Therefore the A2A path cannot currently stream model text incrementally. It only receives completed model turns, which explains why each `[status] working: ...` message and the final artifact arrive as whole blocks.

Studio behaves differently. `pkg/api/chat_runner.go:902-908` forwards partial text events as `text` events and avoids replaying the aggregated final event after partials have already been emitted. This is structural event handling, not content-based de-duplication.

### 2. A2A has no structured tool-progress channel

The current `channels.ProgressSink` accepts only `Progress(text string)`. `pkg/a2aserver/service.go:101-115` converts that text into an A2A `working` status update. In `pkg/channels/manager.go`, function calls are used only to classify model narration as intermediate; tool names and tool lifecycle events are never sent to the sink.

Studio directly emits `tool_call`, `tool_result`, and delegated `subtask_progress` events. A2A therefore has materially less observability than Studio even though both consume the same underlying ADK run.

A safe A2A representation should expose only redacted tool identity and lifecycle, for example:

- `Using Perplexity Web Search…`
- `Perplexity Web Search completed.`
- `Parallel research failed; switching approach.`

It should not expose tool arguments, credentials, raw schemas, or raw tool responses.

### 3. The Apple-news failures include real request cancellation

The live daemon log shows:

- `22:21:34`: first Apple-news A2A run starts.
- `22:21:41`: delegated research starts.
- `22:22:54`: a second Apple-news A2A run starts while the first is still active.
- `22:23:00`: delegated research starts for the second run.
- `22:23:50`: both runs fail at the provider boundary with `context canceled` at the exact same time.
- `22:24:18`: a subsequent Apple-news run starts.
- `22:25:49`: that run completes after about 91 seconds and 15 tool calls.

Thus at least some failures are cancellation propagated from an HTTP/client context, not a normal model-generated fallback alone. The simultaneous cancellation of overlapping runs deserves a concurrency regression test; it should not be assumed that the research provider itself failed independently twice.

### 4. Keepalive and client timeout are separate concerns

`pkg/api/a2a_routes.go:186-200` flushes each real A2A SSE event immediately, but it emits no periodic heartbeat while tools or delegated agents are quiet.

A periodic SSE comment can keep proxies and TCP connections from treating the connection as idle, but the official CLI may apply `--timeout` as a total client deadline. A server heartbeat cannot override a total deadline chosen by the client. Real periodic `working` status events improve user-visible liveness and reset event-idle timers, while SSE comments protect intermediaries; both are useful, but neither should pretend to extend a client-imposed total timeout.

## Recommended implementation

1. Replace the text-only progress contract with a structured, request-scoped event contract carrying text deltas, completed narration turns, tool start, tool completion/failure, and delegated-task progress. Preserve ordering and event identity; never compare content.
2. Map safe tool lifecycle events to A2A `working` status messages containing only redacted display names and states. Do not include arguments or results.
3. Stream final answer text as incremental A2A artifact updates using the protocol's append/last-chunk semantics. The producer must designate the final stream artifact so the completed task is not replayed as a second artifact.
4. Add an SSE heartbeat loop, synchronized with response writes and stopped on request completion. Also emit periodic A2A `working` lifecycle updates during long silent operations if the protocol/client behavior requires real events.
5. Add a concurrency regression test proving cancellation of one A2A HTTP request does not cancel another active task. Trace delegated-task context ownership before changing cancellation behavior.
6. Verify with the official CLI using both a fast inventory request and a long Apple-news request, checking raw SSE ordering, incremental artifact chunks, tool-name progress, independent concurrent runs, and exactly one final answer.

## Non-goals

- No content-based de-duplication.
- No raw tool response streaming.
- No credential, argument, internal URL, command, or schema disclosure.
- No fake progress text generated by the transport layer.
