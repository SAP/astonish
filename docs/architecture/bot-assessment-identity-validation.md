# Assessment identity and validation

Tool-free preparation schemas restrict `source_ids` to assignment, charter, and the exact pinned goal and attachment source IDs. Review schemas are generated from the exact serialized assessment input: `candidate_digest` is a singleton enum, `criterion_id` permits only nonexcluded criteria, `evidence_refs` permits only the captured candidate/artifact/observation references, and `method` permits only `model_assessment`. The runtime supplies the same reference inventory as top-level `available_evidence_refs`; it replaces any supplied inventory rather than trusting it.

Pending reviews retain separate `current_turn` and `deferred_application` objects, both bound to the same candidate and applicable criteria. This does not defer or exempt original requirements. Section-qualified diagnostics identify which assessment failed.

Schemas reduce transport variability; they do not establish correctness. Server validation still requires exact unique coverage, current candidate identity, known evidence references, valid verdicts/methods and nonempty explanations. Satisfied verdicts require evidence. Safe validation errors contain fixed field names, numeric positions and fixed reasons, never rejected identifiers, references or model content. `ErrBotInvalid` remains wrapped for store validation callers.

A valid failed/unverified verdict remains unchanged. Unknown model citation keys are the one conservative boundary conversion: the entire affected criterion becomes `unverified`, with no evidence references and a fixed sanitized finding explicitly saying that no cited support was accepted. A mixed valid/unknown citation list also loses all claimed support; no arbitrary reference is mapped to the candidate. Mechanical checks cannot promote this rejected criterion. Invalid identity, coverage, verdict, method, or explanation still fails closed. Store validation remains strict and never accepts unknown references.

This conversion performs no model retry and no producer/tool execution. A review with a rejected citation is persisted as explicitly unverified and blocks automatic producer repair: a reference error is not authority to replay the work. Other ordinary failed/unverified findings retain the existing bounded repair policy, effect/control replay guards and repair limits. Semantic failures are never format-retried. Only invalid JSON receives the existing single bounded format correction, with the original input and same pinned response schema. Prompts and schema descriptions distinguish citation keys from requirement source IDs, source URLs, tool IDs and body keys. Body contents remain digest-bound candidate evidence, not standalone citation identifiers.

`TestBotWorkCitationModelOnlyReproduction` is an opt-in private saved-candidate capture using `ASTONISH_CITATION_REPRO_DIR`; it sends one model-only HTTP request and saves request/response files with restrictive permissions. It neither executes tools nor writes Bot state. A newly sampled response cannot recover the original discarded response or prove a fresh daemon journey.

Tests: `go test ./pkg/store ./pkg/api -run 'TestBotWork|Test.*Pending' -count=1`. These are package and local wire fixtures, not a live end-to-end readiness claim.
